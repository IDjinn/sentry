# Timings nos logs de requisições + métricas de tempo de processamento

## Contexto (o que já existe)
- O parser nginx **já captura `$request_time`** em `Event.duration_ms` — mas **nada consome** esse campo (não sai no console, eventlog, DB ou dashboard).
- Já existe o histograma `sentry_pipeline_duration_seconds` (pipeline puro), observado no hot path do daemon.
- `$upstream_response_time` é descartado pelo parser; a edge inline não mede nada.

## 1. Timings nos logs de requisições

### 1.1 Core — `HttpData.upstream_time_ms` (`crates/sentry-core/src/event.rs`)
- Novo campo `pub upstream_time_ms: Option<u64>` em `HttpData` (segue padrão serde dos campos Option existentes).

### 1.2 Parser nginx (`crates/sentry-source-nginx/src/parser.rs`)
- `make_capture` (~:247-272): padrão de captura para `upstream_response_time` que aceite lista separada por vírgula (`0.005, 0.003`) e `-`.
- `parse_line` match (~:124-175): braço `upstream_response_time` → parse do **primeiro** valor como f64 → ms em `http.upstream_time_ms` (pula `-`).
- Testes: valor único, lista com vírgula, `-`, e formato combinado com `$request_time`.

### 1.3 EventSummary (`crates/sentry-cli/src/eventlog.rs`)
- Novos campos sempre serializados: `duration_ms: Option<u64>` (de `evt.duration_ms`), `upstream_ms: Option<u64>` (de `http.upstream_time_ms`), `process_us: Option<u64>` (novo — tempo do pipeline).
- `from_processed(pe, process: Option<Duration>)` — assinatura estendida; `None` quando o evento veio da edge já decidido (`Incoming::Processed`, pipeline não rodou).
- Atualizar teste de key-set estável (~:346-394) com as 3 chaves novas (contrato Grafana Infinity).

### 1.4 Console (`print_event`, `daemon.rs:2426-2476`)
- Assinatura ganha `process: Option<Duration>`; linha passa a incluir tempo de requisição (quando houver, ex. `45ms`) e tempo de processamento (ex. `823µs` / `1.2ms`), formatados por helper `fmt_duration`. Call site em `daemon.rs:1098-1103`.

### 1.5 Persistência (`crates/sentry-storage`)
- Migration nova: `ALTER TABLE events ADD COLUMN duration_ms BIGINT; ADD COLUMN process_us BIGINT;`
  (upstream_time_ms já persiste dentro do JSONB `protocol` via HttpData — sem coluna própria, respeitando o modelo de dados).
- `insert`/`insert_with_hash` (`repo.rs:122-187`): bind das duas colunas + parâmetro `process_us: Option<u64>`; atualizar call sites (spawn de persistência no daemon ~:1105-1126).
- `EventRow` + SELECTs de `recent`/`recent_since` (~:190-230): novas colunas.

### 1.6 Dashboard SPA (`crates/sentry-cli/assets/dashboard/`)
- `index.html`: coluna "Time" na tabela de eventos; `app.js` (`refreshEvents`, :137-162): renderiza `duration_ms`/`process_us` formatados, no estilo existente.

## 2. Métricas novas (`crates/sentry-cli/src/metrics.rs` + wiring)

| Métrica | Tipo | Labels | Buckets | Observado em |
|---|---|---|---|---|
| `sentry_ingest_duration_seconds` | Histogram | – | 100µs..1s | Loop de ingest end-to-end (dedupe→pipeline→IA inline→actions), junto do `record_event` (~:1195) |
| `sentry_fork_rescore_duration_seconds` | HistogramVec | `fork=ai\|llm\|ip_lookup` | 10ms..10s | `spawn_fork` de AiFork (:1550), LlmFork (:1716), IpLookupFork (:1996) |
| `sentry_action_dispatch_duration_seconds` | HistogramVec | `action` | 1ms..5s | Loop de dispatch (`execute_with_context`, :1164-1178) |
| `sentry_edge_request_duration_seconds` | Histogram | – | 1ms..10s | `proxy_handler` (proxy.rs:198→:369) e middleware axum, todos os caminhos de saída |

- `Metrics::new()` registra tudo; helpers `record_ingest`/`record_fork`/`record_action_dispatch`.
- Edge: builder `EdgeRuntime::with_request_duration(Histogram)` (mesmo padrão de `with_block_hits`), wire em `daemon.rs:841-847`. `Incoming::Processed` da edge não roda pipeline → `process_us = None` (a latência da edge fica no histograma próprio).

## 3. Grafana (`deploy/grafana/sentry-dashboard.json` + `deploy/honeypot/grafana/dashboards/sentry-overview.json`)
