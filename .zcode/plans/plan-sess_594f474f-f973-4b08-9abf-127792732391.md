## Aplicar o fix de TLS/443 na VPS live (3.17.156.125)

Objetivo: o HTTPS passar a ser terminado pela edge do Sentry (F8), para que payloads como `/login?test=<script>` bloqueiem no 443 igual ao 80. Nenhum código Rust muda — só os arquivos de deployment já editados no turno anterior + operação no VPS.

### 1. Commit + push do fix (main)
Os 5 arquivos já editados e validados localmente (`config validate` e `docker compose config` OK):
- `.github/workflows/docker-publish.yml` — imagem passa a buildar com `FEATURES=sentry-cli/pcap,sentry-cli/edge-tls`
- `deploy/honeypot/docker-compose.yml` — nginx-decoy vira upstream loopback-only (127.0.0.1:8081:80); certs montados no container sentry
- `deploy/honeypot/sentry.toml` — `[edge]` com `tls_listen = "0.0.0.0:443"` + cert/key; source nginx removida
- `deploy/honeypot/nginx-decoy/nginx.conf` — listener ssl 443 removido
- `deploy/honeypot/README.md` — runbook atualizado

O push para main casa o path filter do workflow (`.github/workflows/docker-publish.yml`) e dispara o build.

### 2. Aguardar o build da imagem (CI)
`gh run watch` no workflow `docker-publish` (~10–20 min, amd64 com cache GHA). A imagem nova publica `latest`, `edge` e `sha-<ref>` em ghcr.io.

### 3. Inspecionar o estado live ANTES de mudar algo
SSH (`ubuntu@3.17.156.125 -p 22022 -i LightsailDefaultKey-us-east-2.pem`): baixar via scp `/opt/sentry/docker-compose.yml`, `/opt/sentry/sentry.toml`, `/opt/sentry/nginx-decoy/nginx.conf` para temp local e diffar. O live diverge do repo (logs mostram edge inline no :80 com upstream 8081 — migração parcial já feita à mão; sentry.toml live tem o hash Argon2id real).

### 4. Parchear os arquivos live (com backup `.bak-<timestamp>` no VPS)
- **sentry.toml**: adicionar `tls_listen`/`tls_cert`/`tls_key` no bloco `[edge]` existente (upstream 8081 preservado); remover a source `nginx` se ainda existir; **preservar** hash do admin e demais tweaks live.
- **docker-compose.yml**: mount `./certs:/etc/sentry/certs:ro` no serviço sentry; nginx-decoy publica só `127.0.0.1:8081:80` (remove 443:443/80:80 se ainda presentes); sair o volume `./certs` do nginx.
- **nginx-decoy/nginx.conf**: remover `listen 443 ssl` + diretivas de certificado.

### 5. Migração no VPS (ordem importa)
```bash
cd /opt/sentry
docker compose pull              # baixa a imagem nova com edge-tls
docker compose stop nginx-decoy  # libera 443 (bind conflita com a edge)
docker compose up -d             # recria sentry (nova imagem/config) e o decoy loopback
```
443 já está aberto no firewall Lightsail (o usuário já acessava).

### 6. Verificação live
- `docker logs sentry`: linhas `edge (inline) listening on http` **e** `... on https`
- Payload bloqueado nos dois esquemas: `curl -sk -w '%{http_code}' 'https://3.17.156.125/login?test=%3Cscript%3Ealert(1)%3C/script%3E'` → **403** (idem http://)
- Tráfego normal intacto: `GET /` → 200 nos dois esquemas
- Evento `Block` do teste aparecendo em `/api/events` / dashboard

### 7. Rollback (se algo falhar)
Restaurar os `.bak-<timestamp>`, retag do digest anterior da imagem como `latest` (imagem antiga continua no disco do VPS) e `docker compose up -d`.

Observação: o commit/push é pré-requisito do fix (a imagem com `edge-tls` só existe após o build do CI) e está incluído no escopo aprovado aqui.
