## Plano: Trusted IP Presets (estilo getpagespeed)

Catálogo embutido de listas de CIDRs de serviços confiáveis (PayPal IPN, Stripe, Googlebot, Bingbot, Applebot, Yandex, UptimeRobot, Pingdom). Usuário aprova por nome em `[real_ip] trusted_lists = ["paypal", "googlebot"]`; presets aprovados entram em `TrustSet.never_ban`, herdando todas as garantias existentes: pipeline Allow, edge nunca 403, firewall/nginx recusam ban, ML/LLM não eleva.

### 1. `crates/sentry-core/src/trusted_lists.rs` (novo)
- `TrustedPreset { name, description, ranges: &'static [&'static str] }` + registry `PRESETS`, seguindo o padrão `CLOUDFLARE_IPV4/6` de `trust.rs:21-48`.
- Presets: `paypal`, `stripe`, `googlebot`, `bingbot`, `applebot`, `yandex`, `uptimerobot`, `pingdom` (snapshots estáticos das fontes oficiais).
- Testes: todas as entradas parseiam, nomes únicos.

### 2. Config (`config.rs`, `RealIpConfig` L459)
- Novo campo `trusted_lists: Vec<String>` (default vazio). Nome desconhecido → erro em tempo de carga (estilo ActionKind).

### 3. TrustSet (`trust.rs`)
- Helper `add_never_ban(&mut self, nets)` + `from_config` popula `never_ban` com os CIDRs dos presets aprovados.
- Enriquecimento no daemon reporta `source: "trusted_lists:<name>"`.

### 4. CLI + métricas
- `sentry trusted list`: tabela preset × descrição × nº ranges × ativo (reuso do padrão de `list_feeds`).
- Log no startup listando presets ativos; `sentry feeds check <ip>` indica se cai num preset.

### 5. Docs
- `config/sentry.example.toml` documenta `trusted_lists`; `ARCHITECTURE.md` §8.1 recebe nota. Docs submodule fora do escopo.

### 6. Testes
- `trust.rs`: from_config com preset popula never_ban; nome desconhecido → erro.
- Pipeline parametrizado: IP de preset → `Verdict::Allow` + `override_reason "trusted ip"`.
- Handler CLI testável.

Fora do escopo (roadmap): refresh automático das listas dos vendors; presets como reputation feeds. Entrega com fmt/clippy/test passando, sem commit.
